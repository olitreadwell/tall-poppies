# Contributing

Thanks for contributing. Before you open a pull request or start on an issue,
read the contributing guide. It is written for humans and for AI coding
agents, and it applies to every change in this repository.

Start here:

- `docs/contributing/00-index.md` — reading order and how to use the guide
- `docs/contributing/01-principles.md` — the non-negotiable rules
- `docs/contributing/02-workflow.md` — how a contribution should flow

Issue and pull request templates live in `docs/contributing/templates/`.

If you are an AI agent, `AGENTS.md` at the repository root points at the same
files; follow them exactly. Never fabricate data, a test result, or a claim
that a change works.

## Contributing brand or venue-review content

Content contributions (venue reviews, brand copy, jokes) don't need the full
engineering workflow above. Start here instead:

1. **Suggest a venue** — open an issue with the
   [Venue check request](.github/ISSUE_TEMPLATE/venue_review_request.yml)
   template.
2. **Submit a review** — copy [`docs/reviews/template.md`](docs/reviews/template.md),
   fill it out per [the Meetup Method framework](docs/reviews/review-system.md),
   and open a PR adding it under `docs/reviews/venue-reviews/`.
3. **Keep the voice consistent** — check new copy against
   [`docs/brand/README.md`](docs/brand/README.md) before opening the PR.
4. Use the default PR template for content changes; code changes still
   follow `docs/contributing/templates/PR_DESCRIPTION.md`.
